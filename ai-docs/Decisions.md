# Decisions Log

Append-only record of architectural and design decisions.

2026-09-07 | Gemini 3.8 Flash | Decision: Pull EuroSAT Sentinel-2 starter kernel via Kaggle CLI | Why: Provides reference baseline implementation and data preprocessing pipelines for EuroSAT dataset | Alternatives considered: Writing EuroSAT pipeline from scratch without inspecting Kaggle starter.
2026-09-07 | Gemini 3.8 Flash | Decision: Configure Kaggle access token via ~/.kaggle/access_token and KAGGLE_API_TOKEN | Why: Kaggle's new token format (KGAT_*) uses ~/.kaggle/access_token / KAGGLE_API_TOKEN rather than legacy username/key in kaggle.json | Alternatives considered: Legacy kaggle.json format.
2026-09-07 | Gemini 3.8 Flash | Decision: Use raoofnaushad/eurosat-sentinel2-dataset (RGB EuroSAT) for initial baseline | Why: Fast 93.5MB download containing all 27,000 images in 10 classes, enabling rapid baseline iteration before scaling to 2.2GB multi-spectral TIFFs | Alternatives considered: apollo2506/eurosat-dataset (2.2GB 13-band TIFFs).
2026-09-07 | Gemini 3.8 Flash | Decision: Build modular PyTorch classification pipeline (dataset, model, train, evaluate) with ResNet-18 | Why: Industry standard for computer vision baseline; proven ~95%+ accuracy on EuroSAT; fast training and low VRAM footprint on RTX 3050 | Alternatives considered: Custom shallow CNN (poor transfer learning accuracy), Vision Transformer (much slower training).
2026-09-07 | Claude Opus 4.6 | Decision: Use cu126 index instead of cu124 for PyTorch CUDA install | Why: Python 3.14 wheels are only available on the cu126 index; cu124 returns "no matching distribution" for cp314 | Alternatives considered: Downgrading Python to 3.12 (disruptive).
2026-09-07 | Claude Opus 4.6 | Decision: Resize images to 224×224 for ResNet-18 transfer learning | Why: ResNet-18 was pretrained on 224×224 ImageNet images; feeding 64×64 into pretrained conv filters drastically reduces feature extraction quality | Alternatives considered: Keeping 64×64 (faster but weaker accuracy).
2026-09-07 | Gemini 3.8 Flash | Decision: Use inverse-frequency class weighting in CrossEntropyLoss | Why: Mitigates class imbalance penalty for classes like Pasture (2,000 samples) vs AnnualCrop/Forest (3,000 samples) | Alternatives considered: WeightedRandomSampler (adds epoch overhead and complexity).
2026-09-07 | Gemini 3.8 Flash | Decision: Cache get_device() console logging to output device selection once | Why: Prevents repeated device printouts from cluttering CLI prediction outputs and JSON reports | Alternatives considered: Python standard logging (adds config overhead).
2026-09-08 | Claude Opus 4.6 (Thinking) | Decision: Replace ResNet-18 classifier with SRCNN super-resolution model | Why: Project pivoting from land cover classification to satellite image enhancement. SRCNN (Dong et al., 2014) is the simplest SR architecture — good stepping stone before ESRGAN. 3 Conv2d layers, 69K params, trains in under 1 minute per epoch on RTX 3050 | Alternatives considered: ESRGAN (too complex for first step), EDSR (heavier than needed), VDSR (similar but deeper than SRCNN).
2026-09-08 | Claude Opus 4.6 (Thinking) | Decision: Use L1Loss instead of MSELoss for super-resolution | Why: L1 loss produces sharper results than MSE, which tends to average-out pixel values and create blurry reconstructions. Standard practice in SR literature | Alternatives considered: MSELoss (blurrier), perceptual loss (requires VGG feature extractor, more complex).
2026-09-08 | Claude Opus 4.6 (Thinking) | Decision: Use full 64×64 EuroSAT tiles as HR targets, no sub-patch cropping | Why: EuroSAT tiles are native 64×64 — too small to extract 96×96 sub-patches without first upscaling, which would corrupt the ground truth. Augmentation via flips/rotations instead of spatial crops | Alternatives considered: Upscaling tiles to 128×128 first then cropping (corrupts HR ground truth).
2026-09-08 | Claude Opus 4.6 (Thinking) | Decision: Replace recursive glob with os.walk for dataset scanning | Why: glob.glob with ** recursive=True is extremely slow on Windows for flat directories with 27K+ files. os.walk completes in seconds | Alternatives considered: os.listdir (doesn't support subdirectories), os.scandir (slightly more code).
2026-09-08 | Gemini 3.8 Flash | Decision: Integrate official teammate React 19 + Vite + Tailwind frontend (`model UI/frontend`) from TeraSharp repository | Why: Leverages team's production-grade Leaflet maps, before/after comparison slider, and UI design rather than building an ad-hoc page | Alternatives considered: Custom vanilla HTML/JS page, Streamlit.
2026-09-08 | Gemini 3.8 Flash | Decision: Implement REST backend via standard library `http.server` and `email` multipart parser | Why: Adheres to `Constraints.md` dependency rules (no extra FastAPI/Uvicorn pip installations required) while running natively on Python 3.14 with full CORS support | Alternatives considered: Installing FastAPI + Uvicorn + python-multipart.
2026-09-08 | Gemini 3.8 Flash | Decision: Upgrade to ThreadingHTTPServer with dedicated attachment download endpoints, authentic TIFF generation, and Vite reverse proxy | Why: Solves Windows WinError 10053 socket aborts on concurrent image loading; eliminates cross-origin `<a download>` blocking by making frontend requests same-origin; provides protocol-level `Content-Disposition: attachment` headers; and exports true `.tif` files via Pillow for genuine GeoTIFF compliance | Alternatives considered: Relying solely on client-side JS blob downloads with short timeouts (fails when user pauses in Save As dialog or for cross-origin URLs).
2026-09-10 | Gemini 3.8 Flash | Decision: Remediate GeoRes UI copy, add automated pytest test suite, and demote Kaggle to optional dependency | Why: Reconciles frontend user-facing claims with actual implemented architecture (SRCNN, Pillow/NumPy, ThreadingHTTPServer) without unverified buzzwords; installs pytest and introduces a 10-test unit suite covering SRCNN shapes, dataset lengths/tensors, and optimization steps; reconciles kaggle version pin to >=1.6.0 under optional extras | Alternatives considered: Leaving UI copy as future roadmap claims (leads to credibility issues in code reviews).
2026-09-14 | Gemini 3.8 Flash | Decision: Configure [tool.pyright] extraPaths in pyproject.toml | Why: IDE type checkers and language servers (Pyright/Pylance) default to treating src/ as an import root, causing unresolved import diagnostics on `from src.*` statements despite passing runtime pytest suites. Setting `extraPaths = ["."]` informs static analyzers that project root is an import search path | Alternatives considered: Refactoring entire codebase imports from `src.*` to unqualified imports, or relying solely on manual ignore comments.
